# ADR-0009: Host authentication and player identity

Status: accepted (2026-09-29)

## Decision

### Port

```ts
interface HostAuth {
  /** Verify a bearer token; null if invalid or expired. */
  verify(token: string): Promise<{ hostId: string; displayName: string } | null>;
}
```

Both the HTTP app and `GameService.hostHello` use it. `hostId` namespaces quizzes and sessions.

### AWS: Cognito

- One user pool, Essentials tier (free up to 10,000 MAU per the Price List summary in the research). Self-sign-up is disabled by default: operators create hosts with `aws cognito-idp admin-create-user` (the Terraform module can optionally create one initial admin). Email is the username.
- A public app client (no secret) with authorization code + PKCE, scopes `openid email profile`, and callback/logout URLs of `https://{site}/host`. Managed login on the Cognito prefix domain, which costs nothing.
- The SPA runs the PKCE flow with `fetch` (no Amplify) and keeps tokens in memory, plus a refresh token in `sessionStorage`. It sends the **ID token** as the bearer, because the ID token carries `email` for display.
- Lambdas verify with `aws-jwt-verify` (`CognitoJwtVerifier`, `tokenUse: 'id'`, `clientId`). The verifier fetches JWKS from the Cognito endpoint, which is public, so no VPC or NAT is needed, and caches it per container. `hostId = sub`.
- Managed login supports password managers and paste, which WCAG 3.3.8 (accessible authentication) needs.

### VM: local admin

- Environment: `ZQ_ADMIN_USER`, `ZQ_ADMIN_PASSWORD_HASH` (scrypt, format `scrypt$N$r$p$salt$hash`, generated by `pnpm --filter @zqhoot/server-node hash-password`), and `ZQ_JWT_SECRET` (≥ 32 bytes, required; the server refuses to start without it). `ZQ_ADMIN_PASSWORD` (plaintext) is accepted only for local development and logs a warning.
- `POST /api/auth/login` checks the password with `crypto.scrypt` + `timingSafeEqual`, rate limited to 10 attempts per IP per 15 minutes, and returns an HS256 JWT (`jose`) valid for 12 h. `hostId = local:{username}`.
- Multi-user local accounts are out of scope for v1.

### Players

- Anonymous and per session. `playerId` is a nanoid; the resume token is 256-bit random with only its SHA-256 stored ([ADR-0008](0008-reconnect-resume.md)).
- Nicknames: the engine's `normalizeNickname` runs NFKC, strips `\p{Cf}` and default-ignorables, rejects bidi controls, `\p{Cc}` and private-use characters, collapses whitespace, and allows 2-16 graphemes (`Intl.Segmenter`) within `LIMITS.nicknameMaxBytes` (96 UTF-8 bytes of the normalised name, measured with `TextEncoder`; anything longer is `too-long`). The byte cap exists because graphemes and the 64-unit raw cap do not bound bytes: 16 Indic conjuncts are 192 bytes and 16 flags 128, and 500 of either overrun API Gateway's 128 KB message limit in the host roster ([ADR-0004](0004-wire-protocol.md)). 96 bytes fits a full name in any script (`लक्ष्मी शर्मा` is 37 bytes), and 12 flags is the emoji ceiling. It then builds a folded skeleton for uniqueness: lowercase, confusable map, leetspeak digits. A match from `obscenity` (English dataset + recommended transformers) on the skeleton rejects the name with `nickname-invalid`. We reject rather than silently rename, because the player chose the name and should see why.
- Uniqueness per session uses the `NICK#{skeleton}` claim, so "Ana" and "ana" collide.
- No personal data beyond the nickname and connection metadata. API Gateway access logs are off by default. When enabled, they must exclude query strings.

## Consequences

- The web app never embeds a secret: the Cognito client ID and pool ID are public identifiers.
- Losing `ZQ_JWT_SECRET` invalidates host sessions only. Rotating it logs the admin out.
